# Практическая работа № 3
## «Адаптивная виртуальная экскурсия по объекту»

> **Тема:** Графика на веб-странице: форматы, адаптивность и интерактивность

---

## Выбор объекта

Вы создаёте страницу виртуальной экскурсии. Разрешается:

- Использовать **тему русской усадьбы** — изображения уже есть в папке `/images/` этого репозитория
- Выбрать **собственный объект**: усадьбу, университет, музей, городской парк, архитектурный комплекс, исторический объект

## Обязательные технические требования

### BASE (для всех уровней)
- Семантические теги: `<header>`, `<nav>`, `<main>`, `<section>`, `<footer>`
- **Запрещено** использовать `<div>` вместо семантических элементов
- Один `<h1>`, минимум два `<h2>`, минимум три абзаца
- Блок `<picture>` с WebP и JPEG/PNG fallback и мобильной версией
- Отдельный блок с `srcset` и `sizes` (не внутри `<picture>`)
- `<figure>` и `<figcaption>` для подписи
- Графическая ссылка: картинка внутри `<a>`
- `loading="lazy"` на изображениях ниже первого экрана (у hero — не ставить!)
- Минимум три внешние ссылки, якорная ссылка, ссылка «Наверх»
- W3C Validator → **0 ошибок, 0 предупреждений**

### JUNIOR (дополнительно)
- Галерея: минимум 3 изображения с alt, width/height, подписями, ссылками на увеличенный вариант
- Вторая страница `pages/object.html` с описанием объекта
- Ровно **4–5 осмысленных коммитов** (см. ниже)
- В описании PR: результат проверки DevTools → Network (375px и 1280px)

### PRO (дополнительно)
- Карта ссылок `<map>` с тремя областями: `rect`, `circle`, `poly`
- Рядом с картой — текстовый список `<ul>`, дублирующий навигацию карты
- Вложенная структура: `<dl>` внутри элементов `<ol>` (маршрут экскурсии)
- Стресс-тест: заменить одно изображение текстом ~100 слов, проверить на 375/768/1280px
- Lighthouse Accessibility ≥ 90

## Требования к коммитам

Сделайте **ровно 4–5 осмысленных коммитов** из VS Code. Меньше нельзя.

Рекомендуемая история:

```

feat: add picture and image formats
feat: add srcset sizes and gallery
feat: add second page and links
fix: validate HTML and accessibility
```

> ⚠️ Если весь код появился одним коммитом — работа не принимается.

## Как сдать через Pull Request

1. Сделайте **Fork** этого репозитория к себе (кнопка Fork в правом верхнем углу)
2. Клонируйте **свой форк** на компьютер
3. Создайте ветку `homework-03`:
   - В VS Code: внизу слева кликните на `main` → **Create new branch** → введите `homework-03`
4. Работайте в ветке `homework-03`, в папке `homework-03/`
5. Делайте коммиты по мере работы (минимум 4–5)
6. Push → VS Code предложит опубликовать ветку → соглашайтесь
7. Откройте GitHub → появится жёлтая плашка **«Compare & pull request»** → нажмите
8. PR создаётся **из вашего форка в оригинальный репозиторий** (`fufaev/html_lesson_2_1`)
9. Заполните шаблон описания PR (откроется автоматически) → прикрепите скриншоты
10. Нажмите **Create pull request**

### Что приложить в PR
- Скриншот страницы в браузере
- Скриншот вкладки Elements
- Скриншот W3C Validator (0 ошибок)
- Ответы на два вопроса (почему `<picture>`, чем `srcset`/`sizes` отличаются от `media`)
